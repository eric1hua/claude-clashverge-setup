# 配置决策

## ADR-001：使用现有订阅的正式扩展机制

Clash Verge 的订阅、Merge 和 Script 是持久输入，生成的 `clash-verge.yaml` 会在重载时更新。安装器管理已选订阅的扩展，经 App 正常生命周期重新生成，不重新实现订阅客户端、不添加新订阅、不直接修补运行配置。依据见[生命周期研究](research/clash-verge-lifecycle.md)。

只有显式选中的现有订阅纳入管理。未知自定义脚本默认阻止替换；用户审查并接受完整替换时使用 `--adopt-existing-script`，保留集中快照。

## ADR-002：独立 Claude 组引用准确物理节点名称

首次沿用来源组当前物理节点，后续沿用已保存的选择，避免通用组改变时悄悄改变 Claude 路由。`--node` 是显式选择新目标的接口。

Claude 组不复制订阅凭据；同名节点可从订阅获得更新参数。节点缺失时只含 `REJECT`，不选另一个节点，不加入 `DIRECT`、自动测速、故障转移或负载均衡备用。固定名称不能保证供应商实际出口 IP 不变。此策略的边界是进入 Mihomo、处于规则模式且命中维护规则的流量。

## ADR-003：从本机有效 DNS 继承，补充域名策略

公开安装器不携带个人机器的 DNS 基线。它使用目标机器当前活动配置的有效 DNS，叠加各目标订阅自己的 Merge DNS，然后加入受管理的 Claude 域名后缀策略，用 `#Claude` 显式指定对应 DoH 查询的代理组，保留原 `respect-rules` 值。备用订阅未显式覆盖的字段会继承活动配置基线，不能据此声称其原先独立激活时的完整 DNS 已保持不变。

有效 DNS 必须已经启用，目标不能显式关闭 DNS，且必须已有非空 `proxy-server-nameserver`，否则停止并要求先核对解析路径。安装器不另选通用解析器、bootstrap 或节点地址解析器，保留基线和目标 Merge 中的无关策略。DNS 字段存在和核心检查通过只是配置证据；实际解析路径与未进入代理的请求需要独立验证。

## ADR-004：最小修改与明确冲突

保留不属于 Claude 的规则顺序及节点传输参数。对于已有的 tailnet IPv4 DIRECT 规则，保留其用途并加 `no-resolve`，避免在检查 IP 范围时提前解析公网域名。不会凭空创建 tailnet 服务、地址或通用 VPN 兼容承诺。

不自动修改 TUN、系统代理、时区、TLS 验证、全局 shell 环境或客户端凭据，不普遍启用 VLESS UDP/XUDP。遇到未知扩展时先调查，备份本身不能证明替换它不会损失功能。

## ADR-005：单一入口、私有依赖、可恢复写入

`install.sh` 供手动和 Agent 共用，使用固定 Python 依赖的项目私有环境，不写系统 Python。交互确认发生在具体计划与核心校验之后；`--yes` 适合已明确授权的安装，不跳过其余保护。`--dry-run` 不修改 App，但可准备本地依赖与候选。

核心检查使用私有暂存目录及复制的既有 geo 数据，缺少必需 geosite 数据时停止，避免 dry-run 触发向 App 数据目录写入下载内容。每次实际变更集中备份并记录 SHA-256；写入前检查源文件漂移。回滚校验目标和快照，不覆盖无关并发修改。私有依赖、候选、计划、备份和索引不发布。

## ADR-006：按实际证据报告

源代码测试、候选核心检查、App 重载、运行 API、匿名请求、账号会话是不同证据。仅报告实际执行结果，不以配置保存或安装命令返回代替完整体验验收。

本项目的目标是可观察、可恢复的网络配置，不提供防封号保证，不推断个人账号事件的原因。服务资格与账号问题以官方政策及官方调查为准。
